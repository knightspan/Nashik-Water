# Deployment: Neon → Render → Vercel → simulator → Raspberry Pi

Everything below runs on free tiers. Time: about 30 minutes. You need a GitHub account with
this repository pushed to it.

## 1. Database — Neon (or Supabase)

1. Sign in at <https://neon.tech> → **New project** → name `nashik-water`, region
   **AWS Asia Pacific (Singapore)**, Postgres 16.
2. On the project dashboard open **Connection details**, turn **Pooled connection OFF**
   (use the *direct* connection) and copy the string. It looks like
   `postgresql://neondb_owner:...@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Keep it for step 2. The tables are created automatically by the back end's migrations.

**Supabase instead?** Create a project, open **Project Settings → Database → Connection
string → URI**, and use the **direct connection** (port 5432), not the pooler (6543).
Append `?sslmode=require`. Everything else is identical.

## 2. Back end — Render

1. <https://render.com> → **New → Blueprint** → connect the GitHub repo. Render reads
   [`render.yaml`](../render.yaml) and proposes the `nashik-water-api` web service
   (native Python 3.11 runtime, free plan, Singapore — no Docker).
2. Fill in the variables marked *sync: false*:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `CORS_ORIGINS` | your Vercel URL from step 3, e.g. `https://nashik-water.vercel.app` (you can come back and set it after step 3) |
   | `ADMIN_EMAIL` | the admin login |
   | `ADMIN_PASSWORD` | at least 12 characters |

   `JWT_SECRET` and `INGEST_API_KEY` are generated by Render.
3. **Apply**. Each deploy runs `pip install -r requirements.txt`, then `scripts/start.sh` runs
   `alembic upgrade head` (schema + 7 seeded sites), creates the admin user and stores the
   ingest key (hashed), then starts Uvicorn.
4. Check `https://nashik-water-api.onrender.com/api/health` → `{"status":"ok","database":"ok",...}`
   and open `/docs`.
5. In the service's **Environment** tab, reveal and copy `INGEST_API_KEY` — the simulator
   and the Pi need it.

> Free Render services sleep after 15 minutes without requests and take ~30 s to wake.
> The Pi and the simulator post every few minutes, which keeps it awake.

## 3. Front end — Vercel

1. <https://vercel.com> → **Add New → Project** → import the repo.
2. **Root Directory**: `frontend`. Framework preset: Vite (read from
   [`frontend/vercel.json`](../frontend/vercel.json), which also adds the SPA rewrite so
   `/site/ramkund` works on refresh).
3. **Environment Variables**: `VITE_API_URL` = `https://nashik-water-api.onrender.com`
   (no trailing slash). The build fails on purpose if this is missing.
4. **Deploy**. Note the URL (e.g. `https://nashik-water.vercel.app`).
5. Back in Render, set `CORS_ORIGINS` to that exact URL and redeploy the API
   (several origins: comma-separated, e.g. a custom domain too).

## 4. Environment variables — checklist

| Where | Variable | Example |
|---|---|---|
| Render | `ENVIRONMENT` | `production` (enforces strong secrets) |
| Render | `DATABASE_URL` | Neon direct string with `sslmode=require` |
| Render | `CORS_ORIGINS` | `https://nashik-water.vercel.app` |
| Render | `JWT_SECRET` | generated |
| Render | `INGEST_API_KEY` | generated (first key only) |
| Render | `ADMIN_EMAIL` / `ADMIN_PASSWORD` | your admin login |
| Vercel | `VITE_API_URL` | `https://nashik-water-api.onrender.com` |
| Pi `edge/.env` | `WEB_API_URL` / `WEB_API_KEY` | API URL / current ingest key |
| simulator | `SIM_API_URL` / `SIM_API_KEY` | API URL / current ingest key |

After the first deploy, rotate keys from **Admin → API key** (the new key is shown once).
Changing `INGEST_API_KEY` in Render later has no effect — it is only used when no key exists.

## 5. Run the simulator (6 virtual sites)

**On Render it starts by itself**: `scripts/start.sh` runs `simulator/replay.py` next to the
API (`SIMULATOR_ENABLED=true`, the default), so the demo sites keep updating with no PC on.
When nobody visits for 15 minutes the free server sleeps; on the next visit it wakes and the
simulator back-fills the gap. A powered ESP32 station posting every 10 s keeps it awake.
Real stations: see [STATION.md](STATION.md).

To run it on another machine instead (set `SIMULATOR_ENABLED=false` on Render first, so two
simulators do not post at once):

```bash
cd simulator
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export SIM_API_URL=https://nashik-water-api.onrender.com
export SIM_API_KEY=<INGEST_API_KEY>
python replay.py                                   # back-fills 24 h, then posts every 60 s
```

Viva demo (in a second terminal on the same machine):

```bash
python replay.py --event contamination --site tapovan     # RED within a second, one alert
python replay.py --event rain --site nandini --minutes 90 # AMBER
```

To keep it running on the Pi, create a systemd unit like `edge/systemd/edge-ai.service` with
`ExecStart=.../python replay.py` and the two variables in `Environment=` lines.

## 6. Connect the Raspberry Pi (real Ramkund node)

Full hardware set-up: [HARDWARE.md](HARDWARE.md). Software part:

```bash
# on the Pi (Raspberry Pi OS Bookworm 64-bit)
sudo apt update && sudo apt install -y mosquitto mosquitto-clients python3-venv python3-gpiozero python3-lgpio
git clone <your repo> ~/nashik-water && cd ~/nashik-water/edge
python3 -m venv --system-site-packages .venv && . .venv/bin/activate
pip install -r requirements.txt            # installs ../ml (wqm_ml) with the pinned scikit-learn
cp .env.example .env && nano .env          # set WEB_API_URL and WEB_API_KEY
python edge_ai.py                          # watch the log, then Ctrl+C
sudo cp systemd/edge-ai.service /etc/systemd/system/
sudo systemctl enable --now edge-ai
journalctl -u edge-ai -f
```

`.env` on the Pi:

```
WEB_API_URL=https://nashik-water-api.onrender.com
WEB_API_KEY=<the current ingest key>
NODE_SITE_MAP=node_01:ramkund
```

Within ~2.5 hours of real data the Ramkund marker switches from GREY "Learning baseline" to a
real verdict and its badge reads **LIVE**. If the Pi loses internet, records wait in
`edge/data/edge.db` and are uploaded (idempotently) when the connection returns.

## 7. Verify

- `GET /api/summary` shows 7 sites; the website map shows 7 markers.
- **Admin → Ingest health** shows messages per hour for every site.
- Trigger the demo event: the marker turns red live and **Alerts** shows exactly one alert.
- GitHub → **Actions**: the CI workflow is green.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Website shows "Offline" banner | `VITE_API_URL` wrong, or `CORS_ORIGINS` doesn't list the exact site URL (no trailing slash) |
| `401` from simulator / Pi | the key was rotated: copy the new one from Admin → API key |
| `404 Unknown or inactive site` | site id typo, or the site was deactivated in Admin |
| Render deploy fails on `JWT_SECRET` | `ENVIRONMENT=production` requires ≥ 32 characters |
| `could not translate host name` / SSL errors | use the *direct* Neon/Supabase string with `sslmode=require` |
| Many visitors on one Wi-Fi get `429` | raise `RATE_LIMIT_PUBLIC` (it is per IP; a college network shares one IP) |
