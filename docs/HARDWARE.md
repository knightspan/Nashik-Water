# Hardware: wiring, calibration, firmware and the Raspberry Pi

> **The field design is now the ESP32-C3 station, see [STATION.md](STATION.md).** One
> ESP32-C3 per site reads the probes and posts straight to the cloud over Wi-Fi. This file
> describes the alternative edge-hub set-up (Arduino UNO + ESP8266 + Raspberry Pi running the
> full Random Forest), which is still supported.

This is the path from a box of parts to the **LIVE** Ramkund marker on the website. Do the
steps in order; each one has a check so a problem is caught where it starts.

## 1. Parts

Arduino UNO R3 · NodeMCU ESP8266 · Raspberry Pi 5 (4 GB, 27 W supply) · pH probe with
PH-4502C board · TDS sensor board · turbidity sensor board · DS18B20 waterproof probe +
4.7 kΩ · green/yellow/red LEDs + 220 Ω · 2 active buzzers · 5 V relay module ·
1 kΩ + 2 kΩ resistors · pH 4.01 / 7.00 buffers · TDS standard · distilled/RO water ·
waterproof enclosure + cable glands · perforated PVC guard pipe.

## 2. Wiring

| Arduino UNO | Connects to | Notes |
|---|---|---|
| 5V, GND | all sensor boards VCC/GND | common ground with the ESP8266 |
| A0 | PH-4502C **Po** | analog pH |
| A1 | TDS board **A** | analog TDS |
| A2 | turbidity board **AO** | set the board's switch to analog (A) |
| D2 | DS18B20 data (yellow) | 4.7 kΩ pull-up from D2 to 5 V |
| D6 (TX) | ESP8266 **RX** through divider | 1 kΩ in series, 2 kΩ from ESP RX to GND (5 V → 3.3 V) |
| D7 (RX) | ESP8266 **TX** | 3.3 V is read fine by the UNO |
| D8 | buzzer + | active buzzer |
| D9 / D10 / D11 | green / yellow / red LED (+220 Ω) | normal / natural / alert |

| Raspberry Pi 5 | Connects to |
|---|---|
| GPIO17 (pin 11) | buzzer + |
| GPIO27 (pin 13) | alert LED (+220 Ω) |
| GPIO22 (pin 15) | relay IN (active-low) — warning light / siren |
| 5 V / GND | relay VCC / GND |
| USB-A | Arduino USB (optional: serial fallback, see §6) |

Probe installation: probes hang inside the perforated PVC pipe fixed to the ghat steps,
fully submerged; electronics in the enclosure above the high-water line; turbidity probe
shaded from sunlight. Keep the pH and TDS probes at least 10 cm apart (the TDS excitation
disturbs pH) — the firmware also reads pH first and waits 1 s before TDS.

## 3. Calibrate (firmware/calibration/calibration.ino)

Upload `firmware/calibration/calibration.ino` (Arduino IDE 2, board *Arduino Uno*, libraries
*OneWire* and *DallasTemperature*). Open the Serial Monitor at 9600 baud.

| Step | Do | Write down |
|---|---|---|
| 1 | Multimeter on the UNO 5V pin | `VREF` (e.g. 4.96) |
| 2 | pH probe in **pH 7.00** buffer, wait 2 min | `pH V` → `PH_V7` |
| 3 | Rinse, **pH 4.01** buffer, wait 2 min | `pH V` → `PH_V4` |
| 4 | Turbidity head in clear RO/distilled water (in a dark cup) | `turb V` → `TURB_VCLEAR` |
| 5 | TDS probe in a known standard (e.g. 342 ppm) | `TDS_K = standard / ppm(K=1)` |
| 6 | DS18B20 next to a thermometer | should agree within 0.5 °C |

Enter the values at the top of `firmware/arduino_node/arduino_node.ino`. Check: in the pH 7
buffer the node prints `"ph":7.0x`; in RO water `"turb"` is near 0 and `"tds"` below 20.

Repeat the pH check **weekly** (probes drift) and store the pH probe in KCl storage solution.

## 4. Flash the node and the gateway

**Arduino UNO** — `firmware/arduino_node/`:
1. `WaterStateTree.h` and `SiteBaseline.h` are generated by `python -m wqm_ml.train`
   (copies are already in the folder). After a week of real data, replace the baseline
   with the output of `edge/calibrate_baseline.py` (§7).
2. Upload `arduino_node.ino`. Serial Monitor shows `WQ_NODE_READY v2`, then one JSON line
   per minute: `{"node":"node_01","ph":7.82,"tds":331.4,"turb":15.2,"temp":24.56,"temp_ok":1,"edge_state":0}`.
   The LEDs do a lamp test on start; after 25 minutes the on-board tree starts setting them.

**NodeMCU ESP8266** — `firmware/esp8266_gateway/`:
1. Board package *esp8266* (Boards Manager URL
   `http://arduino.esp8266.com/stable/package_esp8266com_index.json`), libraries
   *PubSubClient* and *ArduinoJson* (v7). Board *NodeMCU 1.0 (ESP-12E)*.
2. Set `WIFI_SSID`, `WIFI_PASS`, `MQTT_HOST` (the Pi's fixed IP), `TS_KEY` (ThingSpeak write key).
3. **Disconnect the UNO from ESP RX while uploading.** Reconnect afterwards.
4. Check on the Pi: `mosquitto_sub -h localhost -t 'wqi/#' -v` prints a line every minute.
   ThingSpeak fields: 1 pH, 2 TDS, 3 NTU, 4 °C, 5 WQI, 8 edge state.

## 5. Raspberry Pi set-up

```bash
sudo apt update && sudo apt install -y mosquitto mosquitto-clients python3-venv python3-gpiozero python3-lgpio
# allow the ESP8266 to connect over the LAN (Mosquitto 2 listens on localhost only by default)
printf 'listener 1883\nallow_anonymous true\n' | sudo tee /etc/mosquitto/conf.d/lan.conf
sudo systemctl restart mosquitto

git clone <repo> ~/nashik-water && cd ~/nashik-water/edge
python3 -m venv --system-site-packages .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env      # WEB_API_URL, WEB_API_KEY, NODE_SITE_MAP=node_01:ramkund
python edge_ai.py
```

Expected log: `model loaded: 1.0.0, threshold 0.300`, then every 5 minutes a line such as
`ramkund GREY Learning baseline 0.0% WQI 243.1` and, after ~2.5 h,
`ramkund GREEN Normal 97.3% WQI 241.6`. Uploads log `uploaded {'received': 1, 'stored': 1, ...}`.

Run it as a service: `sudo cp systemd/edge-ai.service /etc/systemd/system/ && sudo systemctl enable --now edge-ai`
(edit `User=` and paths if your user is not `pi`).

What the service does every 5 minutes, per site:

1. **Window** — median of the last 5 one-minute readings (≥ 3 valid).
2. **Sensor health** (rules, before any AI): `offline` (≥ 3 of the last 5 minutes missing),
   `flatline` (identical values for 30 min), `out_of_range` (pH outside 2–12, TDS/turbidity at
   the sensor's rail, temperature outside 0.5–45 °C or the DS18B20 85 °C reset value).
   Anything but `ok` → **GREY "Sensor check"** — a broken probe can never make a site RED.
3. **Learning** — until 30 windows (2.5 h) exist → GREY "Learning baseline".
4. **Random Forest** on 24 features → Normal / Natural change / Contamination + confidence;
   Contamination is chosen when its probability ≥ 0.30 (tuned on validation data).
5. **Outputs** — outbox (SQLite) → website; RED → buzzer, LED, relay and Telegram (max one per
   site per 30 min); `data/status.json`; `data/latency.csv`.
6. A watchdog posts GREY `offline` if a node goes silent for 10 minutes.

## 6. No ESP8266 / no Wi-Fi at the ghat?

Plug the UNO into the Pi's USB port and run `python edge_ai.py --serial /dev/ttyACM0`. The
same pipeline runs on the USB lines. The Pi can then reach the internet over Ethernet or a
phone hotspot; while offline, records queue locally.

## 7. Learn the real site baseline

The model compares each window with the site's own "normal" (`rel_ph`, `rel_tds`,
`rel_turb`). The shipped values come from simulated data. After **one quiet week** of real
logging:

```bash
cd ~/nashik-water/edge && . .venv/bin/activate
python calibrate_baseline.py --site ramkund --days 7
sudo systemctl restart edge-ai
```

It writes `edge/data/baselines.json` (used by the Pi) and prints the three lines to paste into
`firmware/arduino_node/SiteBaseline.h` for the UNO's offline tree.

## 8. Validation with the real probe

Fill these in for the report (Assignment 9, §9.8.7). Use a bucket of water from the site.

| Bucket test | Expected | Observed | Delay (min) |
|---|---|---|---|
| No change, 2 h | GREEN | | – |
| Add soil, stir (turbidity ↑) | AMBER or RED | | |
| Add salt (TDS ↑) | RED | | |
| Add lemon juice (pH ↓) | RED | | |
| Lift the probes out of the water | GREY (sensor check / out of range) | | |
| Unplug the UNO | GREY offline after 10 min | | |
| Disconnect the Pi from the internet for 30 min | records appear on the website afterwards, no gaps | | |

Latency for the report: `edge/data/latency.csv` (model time per window on the Pi) and the
**Admin → Ingest health** page (end-to-end arrival).

Re-training with real data: export the Pi's readings (`sqlite3 -header -csv data/edge.db "SELECT * FROM readings"`),
label known events, and extend `ml/wqm_ml/train.py` to include them alongside the synthetic sets.

## 9. Maintenance

| Every | Task |
|---|---|
| Week | Clean the turbidity window and probes; pH check in the 7.00 buffer |
| Month | Two-point pH calibration; TDS check in the standard |
| As needed | Replace the pH probe (typical life 6-12 months) |
